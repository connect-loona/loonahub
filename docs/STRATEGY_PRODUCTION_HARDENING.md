# Strategy OS production hardening

## Canonical product surface

`/strategy/` is the only Strategy OS interface. The Hub navigation opens that path
directly. The embedded legacy implementation, its root scripts and the `/strategy-old/`
deployment have been removed. Requests to old Strategy URLs redirect to `/strategy/`.

## Authentication and writes

Every foreground Strategy mutation and export requires both:

1. the existing `loona_auth` Hub perimeter cookie; and
2. a current Firebase ID token belonging to an email in `/members`.

The server resolves the actor from the verified Firebase user. Any `actor` value sent by
the browser is ignored. Strategy server reads and writes use a Firebase service-account
OAuth token and fail closed for a real database when that credential is absent.

Set these Netlify environment variables for Functions before promoting the deploy:

- `FIREBASE_ADMIN_SERVICE_ACCOUNT`: the Firebase project's service-account JSON.
- `FIREBASE_WEB_API_KEY`: the existing Firebase web API key.
- `STRATEGY_INTERNAL_SECRET`: at least 32 random bytes; do not reuse Hub Basic Auth.

The seven background handlers require a timestamped HMAC-SHA256 signature generated by a
foreground Strategy function. Direct, modified, expired and unsigned calls are rejected.

## Firebase Rules

The reviewed Strategy rule block is in `firebase/strategy-rules.fragment.json`. Follow
`firebase/README.md`; merge it into an export of the current complete Realtime Database
rules. Firebase replaces the entire rules document on deploy, so the fragment must never
be deployed alone.

## Reference quality

Creative Direction validation rejects:

- invalid or non-HTTP URLs;
- search-result pages instead of stable source pages;
- placeholder `useFor` values such as `none`, `N/A`, `TBD` and `unknown`;
- vague use notes shorter than four words; and
- references with no concrete lexical connection to the asset's concept, art direction,
  design notes, search query or shot list.

Failures enter the existing bounded model repair loop and cannot be approved as a valid
Creative Direction checkpoint.

## Exports

Canva configuration, API code, pipeline state and UI controls are retired. A validated
deck checkpoint can be downloaded as JSON or PPTX through the authenticated export
endpoint. The export suite deletes all former Canva environment variables before testing
both files; PPTX is verified as a non-empty Open XML ZIP package.

## Verification before merge

Run:

```sh
npm ci
npm run build
npm test
```

The test suite covers authentication failure modes, server-owned actors, HMAC signatures,
all background-handler gates, rules coverage, invalid references, cascading purge,
canonical routing, JSON/PPTX exports, and a 390 x 844 mobile viewport.
